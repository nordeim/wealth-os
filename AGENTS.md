# AGENTS.md — WealthOS

High-signal operating instructions for AI coding agents working in this repo.
Read this before touching anything. Everything here is load-bearing — verify
against the executable sources (`package.json`, config files) if unsure.

## What this repo is

WealthOS: a self-hostable personal-finance workspace (Next.js 16 App Router
+ React 19 + TS strict + Tailwind v4 CSS-first + Prisma/SQLite + Zod +
Vitest/Playwright). It is a functional superset of the original Base44
reference app with visual parity. **main branch only** — never create
branches; push via `docs/ssh_git_wrapper_v3.py` (runbook:
`docs/how-to-git-push-using-ssh-wrapper_SKILL.md`).

## Non-negotiable conventions

- **Gate order is fixed**: lint → typecheck → test → build → smoke → e2e.
  No hosted CI exists; the local gate is the only gate. Never weaken it
  (no `--max-warnings` increases, no skipped tests, no `any`).
- **Pre-ship `bun audit` re-triage** (the security ledger, PAD §10): re-run
  it before every push. A NEW runtime-chain advisory is cured same-session,
  never deferred; dev-toolchain bumps wait for a dedicated dependency round.
  The census + the runtime-zod floor are pinned
  (`tests/security-ledger.test.ts`) — keep the ledger and the pins in
  lockstep.
- **The db lives at `<repo>/db/custom.db`** (`DATABASE_URL="file:../db/custom.db"`
  in `.env`, resolved through `src/lib/db-path.ts` and `prisma.config.ts`
  for CLI, `next build`, AND the running server — the anchor logic is
  pinned by `tests/db-path.test.ts`). Prisma 7 (R-9): the client is
  GENERATED into `src/generated/prisma` (gitignored, eslint-ignored,
  regenerated by the postinstall — run `bun run db:generate` after schema
  edits), the constructor takes the PrismaLibSql driver adapter, and the
  CLI reads its config from `prisma.config.ts`. Never introduce a raw
  `new PrismaClient()` outside `src/lib/db` — the CWD/bun-absolutization
  trap opens a mirror db elsewhere.
- **E2E has its own database**: `playwright.config.ts` pins
  `DATABASE_URL=file:../db/e2e.db` and global-setup reseeds it. The e2e
  port literal ("3100") lives ONLY in `tests/e2e/e2e-port.ts`.
- **API envelope** (`src/lib/api.ts`): every handler returns
  `{ ok, data } | { ok, error: { code, message } }`, guards with
  `requireSession()`, and parses bodies through a Zod schema
  (`src/lib/schemas.ts`). Follow `src/app/api/transactions/route.ts` as
  the reference implementation.
- **Capital + lowercase route twins**: the reference serves
  `/Dashboard` and `/dashboard`. The lowercase dirs hold the real pages;
  the capital dirs re-export via a `.jsx` bridge (TS1149 technique — a
  `.tsx` re-export of a client page breaks the build). Keep both when
  adding sections; `tests/route-case.test.ts` polices the parity.
- **Tailwind v4 gotchas** (see `docs/Tailwind-V4-Validation-Report.md`):
  CSS-first `@theme` in `globals.css`, NO `tailwind.config.js`, NO
  `var()` chains inside `@theme` (semantic tokens are literal hex).
  v4 re-derived the default palette in oklch — the app pins the v3
  values it needs (shadows/blur renames included). New colors must be
  re-pinned the same way, not pulled from v4 defaults.
- **The mobile drawer is a plain conditional `<div>`**, NOT Radix Dialog —
  Radix marks outside content `aria-hidden`, which hides the header's ✕
  from the a11y tree (a real e2e failure). Don't "upgrade" it.
- **The AI coach is deterministic and local** (`src/lib/ai.ts`), per the
  replicate-web-app AI-stub policy — no network calls, no API keys.
- **`pageMetadata()`** (`src/lib/site.ts`) is the only metadata factory;
  titles are absolute strings; sitemap/robots/manifest derive from it.
  `tests/metadata.test.ts` + `tests/pwa-metadata.test.ts` pin the family.
- **Session cookie is `neo_session`** (HMAC-signed, 7-day TTL) — the name
  survives from the scaffold; the smoke ladder greps it by name.

## Testing rules

- Write the failing test first for new logic (RED → GREEN → REFACTOR).
- Bug fixes need a regression test that fails before and passes after.
- Architecture contracts are pinned in tests (`gate-script`, `db-census`,
  `docs-counts`, `route-case`, `nav-config`, `page-titles`). When a
  contract legitimately changes, update the pin in the same commit and say
  why — never delete a pin to make a gate pass.
- The seed's transaction total is **date-dependent by design** (never seeds
  future rows); the census pins it as bounds 54..108, static entities
  exactly. Recalibrate bounds only when the generator plan changes.
- a11y: every page must stay axe-clean at WCAG 2.2 AA; contrast fixes
  prefer darkening one Tailwind step over restyling.

## Git

- main only, Conventional Commits (`feat:`, `fix:`, `test:`, `docs:` …),

- Never commit: `.env`, `db/*.db`, `dev.log`, `test-results/`, keys,

## Gotchas that have bitten before

- **A phantom breakpoint variant silently generates NO CSS in Tailwind v4**
  (session-207, F-207a): `hidden xs:inline-flex sm:inline-flex` hid the
  mobile Synced pill below `sm` because `xs` is not a default v4
  breakpoint and this repo ships no config file — v4 drops unknown
  variants without warning. `tests/shell-parity.test.ts` now scans src
  for `xs:`/`2xs:`/`3xs:` variants; use only real breakpoints
  (sm/md/lg/xl/2xl…) or define the variant in `@theme`.
- **An unknown utility TOKEN is silently inert in Tailwind v4** (the
  F-207a lesson's token edition, cured session 209): classes like
  `text-card-foreground`/`bg-card` generate NO CSS unless
  `--color-card-foreground`/`--color-card` are pinned in `@theme` — the
  session-208 usages were inert until the pins landed
  (`globals.css` + the `.dark` runtime flip). Copying a reference class
  string means porting its tokens too. Pinned in
  `tests/parity-209.test.ts`.
- **`@source not` prose carriers can bite back three ways** (session
  224, F-224v — the `@source not` family): (a) a CSS BLOCK COMMENT
  containing a glob (`skills/**/html-tailwind.csv`) terminates at the
  `*/` INSIDE the glob — the comment ends early and PostCSS fails;
  never put a `*/`-bearing glob inside a CSS comment. (b) root-level
  markdown (`neo-crm_SKILL.md` at the repo root) is NOT covered by
  directory excludes (`@source not "../../skills"` etc.) — it needs
  its own root-level glob. (c) comments carrying class-like strings
  (`text-success` in a docblock) get content-scanned and emit dead
  CSS — reword the comment; don't add a glob for it (the F-220
  lesson). The before/after build probe (a dead sentinel disappears,
  a live utility stays) is the verification pattern.
- **The F-223k logout bump is USER-level — it poisons e2e order**
  (session 224, F-224d): `POST /api/auth/logout` increments the USER's
  `tokenVersion`, evicting EVERY live cookie for that user. An e2e leg
  that logs out the DEMO account kills the shared `auth.setup`
  storageState (its cookie embeds the pre-bump version) for every
  later shared-state spec — they all land on the login wall. Revocation
  legs ride a SCRATCH user (the data-import doctrine); the sign-out
  family re-mints the shared state in `afterEach` (mobile-navigation
  spec). Symptom signature: every spec after the logout leg fails with
  login-wall redirects while each passes in isolation.
- **Tailwind v4's `rounded-full` emits the infinity-form radius**
  (`border-radius: 2147483647px`, not `9999px`) — smoke leg 15 pins it;
  don't "fix" it to 9999px.
- **Bun absolutizes relative `file:` DATABASE_URL** against the `.env`
  file's directory when running scripts — `src/lib/db-path.ts` re-anchors;
  don't bypass the `db` singleton.
- **Radix Dialog + outside interactive elements** = `aria-hidden` trap (see
  the mobile drawer note above).
- **`document`/`window` in module scope** breaks SSR — use the `useIsDark()`
  hook pattern (`src/components/layout/theme.tsx`) for theme reads.
- **Deleting a file still imported by `layout.tsx`** kills the build with an
  oblique TS1149 — check importers before deleting under `src/app`/
  `src/components/layout/`.
- **A stale `node_modules/.prisma`** after schema edits: rerun
  `bun run db:generate` before blaming the query code.
- **recharts v3 silently sorts `<Legend />` payloads alphabetically**
  (session-208, F-208f): the legend settings default `itemSorter: 'value'`
  reorders series by NAME (Expenses, Income, Net) while the reference
  (recharts v2) preserves series order — and v3 REMOVED the explicit
  `payload` prop. The cure: `<Legend itemSorter={null} />` (the selector
  skips `sortBy` when the sorter is falsy). Pinned in
  `tests/parity-208.test.ts`.
- **A script's direct-execution guard must be an EXACT basename match**
  (session-210, F-210c): `"fullpage-sweep.ts".endsWith("sweep.ts")` is
  TRUE — so the moment fullpage-sweep.ts imported `./sweep` (the R-4.4
  re-anchor), sweep.ts's suffix-form guard fired THE SWEEP inside the
  fullpage process: zero → capture → RESEED mid-run, corrupting the
  maiden's measurements until the zero-data sentinel caught it (F-210b).
  All five direct-execution guards (the four capture tools +
  prisma-env, session-215 R-12/F-215l) are now `path.basename(
  process.argv[1]) === "<name>.ts"` — a guard a sibling's filename can
  satisfy is not a guard. Pinned in `tests/fullpage-sweep-tool.test.ts`
  + `tests/script-guards.test.ts`; long-running
  capture tools must also verify their workspace state mid-run (the
  zero-data sentinel pattern) instead of trusting a one-time setup.
- **bun HARD-BLOCKS better-sqlite3** (session-213, R-9): `require`
  loads but the constructor throws `not yet supported in Bun`
  (oven-sh/bun#4290) — and prisma 7's upgrade guide names exactly that
  adapter for SQLite. The bun-compatible runtime chain is
  `@prisma/adapter-libsql` + `@libsql/client` (NAPI, verified live under

- **The `.dark` block must flip the APP-NATIVE tokens too** (session-217,
  F-217c): R-11 flipped the shadcn neutral set but left
  `--color-surface/foreground/ink/muted-ink/line/line-soft/line-strong`

  base-layer `.dark body { color }` rule can NEVER beat the
  `text-foreground` utility on `<body>` — flip the TOKEN, not the rule.
  Pinned in `tests/dark-tokens.test.ts` + the a11y dark legs.
- **A DOM-scoped outside-close listener fires on PORTALED Radix
  surfaces** (session-217, F-217a): the Expenses filters popover's
  pointerdown guard closed on Select OPTIONS — they live in
  `document.body` through `SelectPrimitive.Portal`, so "outside the
  popover group" is their normal address; the popover unmounted

  Escape leg never covered the pointer path). Exclude the portal
  carriers (`[role="option"]`, `[role="listbox"]`,
  `[data-radix-popper-content-wrapper]`) and scope expanded-button
  guards to the trigger, not every `button[aria-expanded]`. Pinned in
  `tests/expenses-popover.test.ts` + the mouse-pick e2e leg.
- **A popover's TOGGLE must be excluded from its own outside-close
  guard — or the click reopens what the pointerdown closed**
  (session-218, F-218b): the F-217a cure removed the bare
  `button[aria-expanded]` guard without landing the scoped replacement
  its comment claimed — the trigger matches no exclusion (its
  aria-label rides the popover PANEL, a DOM sibling, so `closest()`
  never matches it), pointerdown fired close, the effect detached, and
  the click toggled false→true: the toggle flicker-reopened
  (live-reproduced; the e2e battery covered the pick and the outside
  click, never the trigger toggle). The cure is a `filtersTriggerRef` +
  `contains()` — and the pin asserts the POSITIVE form (the guard
  exists), not merely the bare selector's absence. A negative-only pin
  let the regression ship.
- **The fresh-visitor DEFAULT THEME is DARK on app routes; the auth faces
  FORCE light** (session-219, F-219c/F-219t): the reference's authenticated
  shell renders html.dark for fresh visitors (its auth faces serve light
  always — live-measured, its choice persists server-side per user; ours
  persists in localStorage, the superset). The resolution lives in
  `src/lib/theme-default.ts` (the pure seam), mirrored INLINE by the
  no-FOUC bootstrap in the root layout (pre-paint JS cannot import) and
  re-applied by the ThemeProvider's pathname effect (client navigations —
  the login→dashboard and logout→login holes the bootstrap cannot see).
  Never parse a stored theme path around the seam; the
  `tests/theme-default.test.ts` source pins keep the three honest.
- **A per-navigation API read cannot carry a per-IP rate bucket**
  (session-219, F-219m's refinement): /api/dashboard fires on EVERY
  hydrate — the e2e battery, the sweep/fullpage/census toolchain, and any
  fast-navigating user legitimately exceed any cap inside one window (the
  maiden census run tripped mid-run and rendered the store-error banner
  into every capture). The heavy EXPLICIT actions carry the buckets
  (writes 60/15 — on EVERY mutating handler since session-220/F-220c:
  the collection POSTs AND the `[id]` PUT/DELETE pairs, budgets
  DELETE, settings PUT, users PATCH — export 240/15, search 60/15);
  the aggregate read stays
  unbucketed BY DESIGN (the decode is pinned in the route's docblock).
- **Stored calendar dates are UTC MIDNIGHT — local-accessor reads
  mis-bucket them west of UTC** (session-218, F-218d): `dateField`
  accepts `yyyy-mm-dd`, `new Date("2026-11-01")` parses as UTC
  midnight, Prisma returns `.000Z` — then `sameMonth`/`startOfMonth`
  and the display seams read LOCAL parts. In America/New_York a Nov 1
  transaction rendered 10/31 and bucketed into October (rent on the
  1st), and the edit prefill — a RAW `new Date(editing.date)` —
  re-stored the wrong day. The UTC sandbox is why every gate was
  blind. The cure: `toDate()` re-anchors the exact UTC-midnight ISO
  form to local midnight of the same calendar date (true timestamps
  keep their instant; Date inputs pass through); NEVER parse stored
  dates with a raw `new Date()` — route through `toDate`. Pinned with
  TZ-switching tests (`process.env.TZ = "America/New_York"` — both
  engines honor dynamic TZ; verified). Session-220 (F-220a): the
  seam's pattern now takes the BARE `yyyy-mm-dd` form too — a cure
  that doesn't match the caller's input FORM is a no-op (the F-219e
  analytics "cure" routed date-INPUT values through a pattern that
  matched only the stored `.000Z` form; live-reproduced). Pin the
  FORM, not just the call site. Session-221 (F-221a/c): the SAME
  class shipped INSIDE the F-220m cure — `stageCsvDate` read LOCAL
  accessors off every parse, so the bare bank-CSV form (UTC-midnight
  parse) staged a day early west of UTC and the Z-form a day late
  east of UTC. The seam is now FORM-BRANCHED (bare ISO → the literal
  groups; UTC-designated → UTC accessors; locale forms → local), and
  the lesson generalizes: EVERY date-taking seam gets TZ-switching
  behavioral pins over EACH accepted form — a pin that runs only
  under the runner's ambient UTC proves nothing about the zone edges.
  Session-222 (F-222a/b): the form-branch ITSELF carried the class
  twice more — the designator regex was CASE-SENSITIVE (RFC-3339
  lowercase `z` fell to the locale branch: a day off on both zone
  edges, live-reproduced) and it recognized only ±00:00 (a +09:00
  cell staged the VIEWER's calendar date — the identical file
  imported different books for different users). The completed
  doctrine: a zone-designated ISO datetime stages its WRITTEN date
  LITERAL (the offset's own wall-clock — never an instant to
  zone-shift, never the viewer's zone); partial ISO forms (yyyy,
  yyyy-mm) are REJECTED (V8 parses them as UTC day-1 — a skip beats
  an invented day); and EVERY literal-staging branch round-trips its
  calendar (02/30 rolls to Mar 2 in V8's lenient parser — null it).
  When you enumerate "the forms this seam accepts", ENUMERATE THE
  DESIGNATORS TOO: `[Zz]`, `±HH:MM`, `±HHMM` — and pin each.
- **A logout that REVOKES poisons the e2e suite's shared storageState**
  (session-223, F-223k): the tokenVersion bump is per-USER — the
  static cookie `tests/e2e/.auth/user.json` (minted once by
  auth.setup.ts) embeds the pre-bump version and dies at every later
  test's getSessionUser comparison. Every sign-out leg must
  RE-AUTHENTICATE and overwrite the state file before it ends
  (the `reMintSharedAuth` helper in mobile-navigation.spec.ts) —
  and each re-auth lands in the same per-IP login bucket (10/15min)
  the setup login rides, so count the suite's logins before adding
  more.
- **A STRICT-REGEX ALLOWLIST can never outrun the V8 date parser —
  probe the engine's ACTUAL acceptance set before claiming a family
  closed** (session 226, F-226a): R-22's designated-tail completion
  claimed "recorded residual: nothing" while seven escape families
  (case-insensitive utc/gmt, the RFC-822 weekday prefix, separator
  lenience, the meridiem, V8's named zones, compound UTC±/GMT±
  tails, month-year + tail) still staged the viewer's calendar —
  "Dec 31, 2026 8:00 PM EST" staged 2027-01-01 (a wrong YEAR).
  The doctrine: probe `new Date(form)` for every form you intend to
  cover AND the neighbors you don't (V8 accepts UT/EST/EDT/CST/CDT/
  MST/MDT/PST/PDT but rejects CET/JST/BST/AEST — the rejected ones
  null safely through the whole-parse guard), and never write
  "no residual" — write the PROBED residual.
- **A SIBLING REPO'S RETIREMENT DOCTRINE DOES NOT TRANSFER — probe
  THIS reference before porting a class retirement** (session 226,
  F-226i): the neo-crm F-129c1 lesson retired `ring-offset-background`
  because THAT reference's background token was the divergent value;
  here the class string was byte-extracted from THIS reference, whose
  own triggers carry it (live-probed: the reference's Analytics tabs
  compute the offset to its --background). The audit's "retire it
  here too" claim was INVERTED — our TABS_SEGMENTED lacked the class
  and painted a WHITE focus halo on dark pages. The F-207c
  withdrawal pattern exists for exactly this: re-probe, then record
  the adjudication.
- **A bare-offset tail on a two-group rejector EATS THE MOST COMMON
  FORM** (session 226, F-226a's design hazard): extending the numeric
  month-year partial rejector ("2026/11") with the full designated
  tail would make every ISO date match it — "2026-11-01" reads as
  year / 11 / -01-offset and NULLS. The rejection family carries the
  named zones and compound suffixes ONLY; the bare-offset partials
  ("Nov 2026 +09:00") are V8-NaN and null through the locale arm's
  whole-parse check. Enumerate what a widened tail can ALSO match
  before widening it.
- **A capture tool that signs up scratch accounts must NOT ride the
  dev database** (session 225, F-225e): a scratch user created against
  `db/custom.db` SURVIVES `db:seed` (the reseed's deletes are
  owner-scoped) and `db:census` MISMATCHes at users=2 — the R-21
  capture set shipped that state silently (its gates verified the
  census BEFORE the captures ran). The e2e doctrine now covers the
  capture family: `db/captures.db` recreated + seeded per run, the
  spawned dev server carries `DATABASE_URL=file:../db/captures.db`
  explicitly (an upgrade of the F-123a1 unset guard), a census
  tripwire fails the run at exit, and a server already on :3000 is a
  REFUSAL, not a reuse — a reused server's database is unknowable.
  `db/captures.db` is gitignored with the other dbs.
- **An equal z-index paint order is decided by DOM order — the LATER
  element wins** (session 225, F-225d): the skip link's focused reveal
  (z-50) painted UNDER the sticky mobile header (z-50, later in DOM)
  — the focused link was invisible below lg while every gate stayed
  green (the e2e leg ran 1280-only; axe cannot model paint order).
  `elementFromPoint` at the element's own center is the honest form
  of "is the focused element visible"; when raising a surface above a
  layer family, clear the whole family (z-[60] over the z-50
  header/drawer/dialog set) and stay under the toasts.
- **The a11y two-gate must SCROLL before `axe.run()`** (session-221,
  F-221f): axe evaluates only what is (or can be) rendered in view —
  at the fixed 1280×800 / 390×844 viewports, every below-the-fold
  contrast failure passed every gate (the Settings Export card's
  3.38:1 ink shipped at session 208 and survived 13 sessions of
  green two-gates; live A/B: 0 violations unscrolled, the failure

  `tests/e2e/a11y.spec.ts` steps `<main>` to the bottom before every
  assertion — new below-the-fold surfaces are the gate's blind spot
  no longer.
- **A relative symlink target resolves from the LINK'S OWN DIRECTORY —
  a root-targeted alias inside docs/ must carry `../`** (session 227,
  F-227a): an owner commit created `docs/worklog.md → worklog.md`
  intending the ROOT log, but from docs/ the target resolves to
  `docs/worklog.md` itself — an infinite loop. Nothing in lint/tsc/
  unit/e2e walks it; only `bun run build` does (Turbopack's
  DirAssetReference, via the upload routes' file tracing) and it
  FAILED the build at HEAD. The honest form is
  `docs/worklog.md → ../worklog.md`; `tests/parity-227.test.ts` pins
  the alias resolves AND matches the canonical content. When adding
  any symlink to the tree, resolve it from its own directory and run
  the build leg — the loop shape passes every other gate.
- **A doctrine-uniformity "tidy" can itself be the bug — prove which
  side of the identity a raw parse sits on before routing it through
  the seam** (session 228, F-228c): the Analytics CSV export's
